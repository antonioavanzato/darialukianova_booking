# Instagram comment-to-DM бот

Под постом Даша пишет «напишите слово **НОТЫ** в комментариях — пришлю ноты
в личные сообщения». Бот ловит вебхук о новом комментарии, ищет ключевое
слово и отправляет автору личное сообщение с заранее заданным текстом.

## Изоляция от системы записи

Это отдельный сервис, ничего общего с букингом:

| | Запись | Instagram-бот |
|---|---|---|
| Функция | `daria-booking-api` (`yc/backend`) | `daria-ig-bot` (`yc/ig-bot`) |
| API Gateway | `daria-booking-gw`, `/api/{proxy+}` | `daria-ig-gw`, `/api/ig/{proxy+}` |
| Таблицы YDB | `slots`, `windows`, `bookings`, `push_subscriptions` | `ig_triggers`, `ig_replied`, `ig_token` |
| Деплой | `yc/deploy.sh` | `yc/ig-bot/deploy.sh` |

Общего только два: одна и та же база YDB (разные таблицы) и один и тот же
`JWT_SECRET` — чтобы вход в админку был единый. Шлюз бота сделан отдельным
намеренно: так выкладка бота физически не может задеть форму записи.

## Что уже сделано на стороне Meta

- Приложение `daria-bot` создано, тип Business, без страницы Facebook.
- Подключён продукт «API setup with Instagram business login».
- Запрошены разрешения `instagram_business_basic`,
  `instagram_business_manage_comments`, `instagram_business_manage_messages`.
- Standard Access, без App Review (используется на своём аккаунте).

## Что осталось сделать

1. **Тестер.** Meta → приложение → Роли → добавить аккаунт Даши как
   Instagram Tester; с её аккаунта принять приглашение в
   Настройки → Для профессионалов → Приложения и сайты.
2. **Схема.** Консоль YDB → «Запросы» → выполнить `schema.sql` из этой папки
   (существующие таблицы не затрагиваются, только `CREATE TABLE` новых).
3. **Деплой.**
   ```bash
   FOLDER_ID=b1g5f3ibgkjuf25m2vp9 \
   YDB_ENDPOINT='grpcs://ydb.serverless.yandexcloud.net:2135' \
   YDB_DATABASE='/ru-central1/…/…' \
   JWT_SECRET='тот-же-секрет-что-у-функции-записи' \
   IG_VERIFY_TOKEN='придумать-строку' \
   IG_APP_SECRET='…' IG_APP_ID='…' \
   ./yc/ig-bot/deploy.sh
   ```
   Скрипт выведет `IG API URL` и готовый `Webhook URL`.
4. **Админка.** Подставить `IG API URL` в `yc/admin/index.html`, переменная
   `IG_API_URL` (в самом низу скрипта, блок INSTAGRAM).
5. **Webhook в Meta.** Приложение → Instagram → Webhooks: Callback URL —
   `https://<домен>/api/ig/webhook`, Verify Token — то же значение, что в
   `IG_VERIFY_TOKEN`; подписаться на поле **`comments`**.
6. **Первый токен.** Через Meta UI («Generate token» у подключённого
   аккаунта) получить долгоживущий токен и вставить его во вкладке
   «Instagram» → «Подключение» вместе с ID бизнес-аккаунта. Дальше токен
   продлевается сам: таймер `daria-ig-token-refresh` раз в сутки будит
   функцию, и та обменивает токен, когда до конца жизни остаётся меньше
   20 дней.
7. **Проверка.** Добавить ключевое слово во вкладке «Instagram», под своим
   постом написать его с другого аккаунта — придёт личное сообщение.
   В админке у слова вырастет счётчик «сработало раз».

## Как это работает внутри

- `GET /api/ig/webhook` — верификация подписки, возвращает `hub.challenge`.
- `POST /api/ig/webhook` — события. Тело проверяется по подписи
  `X-Hub-Signature-256` (если задан `IG_APP_SECRET`), берутся `changes` с
  полем `comments`.
- Совпадение слова ищется по нормализованному тексту (нижний регистр,
  `ё`→`е`, знаки препинания в пробелы), как отдельное слово или фраза.
- Дедупликация: перед отправкой `comment_id` пишется в `ig_replied`; если
  Meta пришлёт то же событие ещё раз, второго сообщения не будет. Если
  отправка сорвалась, отметка снимается — повтор от Meta даст ещё шанс.
- Свои же комментарии (от `ig_user_id`) пропускаются, чтобы бот не отвечал
  сам себе.
- Отправка: `POST /{comment-id}/private_replies`, при отказе — запасной путь
  `POST /{ig-user-id}/messages` с `recipient.comment_id`.
